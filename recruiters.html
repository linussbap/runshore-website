What I built

How RunShore works

Design decisions that keep every action repeatable, observable and honest.

One console, one script per action

A React web console calls a Go (Gin) API. For every button, the backend runs exactly one Bash script, logs its output and returns the result. The UI never runs commands itself, and every script can be run by hand with the same result.

Same workflow on four platforms

Each script takes its target from one setting, so the same scripts deploy and test on local Kubernetes (minikube), AWS EKS, Azure AKS and Google GKE. Cloud clusters are built with Terraform.

Databases through Kubernetes operators

PostgreSQL (CloudNativePG), MySQL (Percona XtraDB Cluster), MongoDB (Percona Server for MongoDB replica set) and SAP ASE (single instance, from the client's own SAP installer).

Monitoring built in

RunShore deploys PMM, New Relic or Splunk and registers each database with it, with workload and assessment dashboards for every database.

Recovery is tested and recorded

Point-in-time recovery, failover and replication tests are scored PASS or FAIL, timed, and written to a results ledger with a link to their evidence.

Read-only AI assistant

ASK AI explains what happened using nine read-only tools and the recorded evidence. It cannot change the platform.

Working principles

  • Every action starts from a clean environment and can be run again safely.
  • One change at a time, with a backup and an automatic restore if tests fail.
  • Failures are shown, never hidden.
  • No secrets in code, logs or screenshots.
  • Cloud resources are destroyed and the destroy is verified.
