Cost control

Know what is running. Prove it is gone.

Cloud test environments cost money while they run. RunShore can list what is still running in an AWS, Azure or Google Cloud account, check that a teardown left nothing behind, and reports a destroy as failed if anything is left.

Cloud Audit

Resource Inventory

A read-only scan of the cloud account, shown with live progress in the Activity panel. It reports each type of resource the platform creates, and says so plainly when a type has none:

AWS: EKS clusters, EC2 instances, VPCs, subnets, security groups, network interfaces, load balancers, target groups, EBS volumes, IAM roles.
Azure: AKS clusters, resource groups, VM scale sets, virtual networks, network security groups, network interfaces, load balancers, public IPs, managed disks, managed identities.
Google Cloud: GKE clusters, compute instances, VPC networks, subnets, firewall rules, forwarding rules, persistent disks, static IPs, service accounts.

Cloud Audit

Cleanup Validation

A read-only check that nothing created by the platform remains in the account. It returns CLEAN or lists what is left. Latest result on each cloud, as written in the run logs:

AWS, 12 November 2026: RESULT: AWS CLEAN -- nothing found in eu-west-2
Azure, 12 November 2026: AZURE ENVIRONMENT IS CLEAN
Google Cloud, 6 October 2026: GCP COST-BEARING ENVIRONMENT IS CLEAN

Destroy

A destroy that proves itself

Cloud destroy runs four steps: release the cloud resources Kubernetes created, Terraform destroy, sweep leftovers, then run Cleanup Validation as a gate. If anything is still there, the destroy is reported as failed, not finished.

Workloads

Workloads stop by themselves

Load generators stop after a set time: 60 minutes by default, changed in ADMIN (0 turns the limit off). A forgotten test does not keep a cluster busy or fill its disks.

Local

Pause instead of rebuild

On local Kubernetes, SHUTDOWN asks the PostgreSQL, MySQL and MongoDB operators to pause their clusters, so the nodes stop in order and the data is kept. If a database does not pause in time, the cluster is left running rather than stopped hard. A restart needs no rebuild and no crash recovery.
