Client App run-through

Follow the application journey

The RunShore Client App is one web console that runs on the operator's own machine. Every button is an API call, and the backend runs exactly one script for it, logs the output and returns the result. The same scripts can be run by hand with the same result.

Client applications evidence pack → Open the demo story

Choose a scope

Local Kubernetes (minikube), AWS EKS, Azure AKS or Google GKE. One script serves all four; the scope picks the target.

Build the environment

DEPLOY, VALIDATE, VERIFY and DESTROY in the top bar, with SHUTDOWN and RESTART for local Kubernetes. Cloud clusters are built with Terraform.

Deploy, load and test a database

The DATABASE panel deploys PostgreSQL, MySQL, MongoDB or SAP ASE/Sybase, starts a workload, and runs point-in-time recovery, failover and replication tests, each scored PASS or FAIL and timed.

Observe and review

The OBSERVABILITY panel deploys PMM, New Relic or Splunk and registers each database with prebuilt dashboards. ACTIVITY, CONTAINERS, SCOREBOARD, TIMINGS and INSIGHTS show what happened.

Assessment results

Every test writes PASS or FAIL, timings and an evidence path to a results ledger. Failures are kept, not hidden. PITR has passed on all three clouds for PostgreSQL, MySQL and MongoDB; failover and replication are recorded on local Kubernetes.

Cost control

Cloud Audit lists what is running in a cloud account and checks a teardown left nothing behind; VERIFY confirms it after a destroy.

Real applications on RunShore databases

Client applications

Four ordinary applications run against the databases RunShore deploys on local Kubernetes, each with its own workload, to show what a database event looks like from the application's side.

MySQL

WordPress

Connects to the Percona XtraDB Cluster through HAProxy.

MongoDB

IDURAR (ERP/CRM)

Node.js and React application connected to the MongoDB replica set primary; the connection follows a failover.

PostgreSQL

Django

Python web application connected to the CloudNativePG read-write service.

SAP ASE / Sybase

Customer Orders (Spring Boot)

Java application that reads through a read-only database login.

One script starts, stops and reports on the four applications; connections are re-established automatically when database pods restart. The Client App itself is not hosted publicly: it runs on the operator's machine. Use the demo story and evidence library to see it working.
