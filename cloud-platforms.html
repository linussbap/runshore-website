Cloud platform learning & comparison

Choose cloud services by workload—not by brand preference

Learn the advantages, operational trade-offs and workload fit of AWS, Microsoft Azure and Google Cloud. The right choice depends on existing skills, architecture, compliance, service requirements and total cost of ownership.

aws Amazon Web Services

Where AWS can be advantageous

  • Broad range of infrastructure and managed services gives architects many design choices.
  • Amazon EKS offers a managed Kubernetes control plane integrated with AWS compute and networking.
  • Multiple storage, database, identity, networking and analytics services support varied workload patterns.
  • Global infrastructure and Availability Zones support regional and resilient designs.

Trade-offs to investigate

  • Service breadth can increase the learning curve and architecture decision effort.
  • Cost depends on multiple dimensions: compute, storage, data transfer, managed services and support.
  • IAM, networking and account structures require deliberate governance.

A Microsoft Azure

Where Azure can be advantageous

  • Can fit well where Microsoft identity, Windows Server, SQL Server, Microsoft 365 or enterprise agreements are already important.
  • AKS provides managed Kubernetes within Azure's platform ecosystem.
  • Azure Arc can project and manage supported on-premises and multicloud resources through Azure management services.
  • Integrated identity, policy, monitoring and governance services are useful in enterprise environments.

Trade-offs to investigate

  • Licensing and service dependencies need to be assessed carefully.
  • Hybrid and multicloud governance introduces its own design and operational complexity.
  • Service configuration and pricing can vary by region and architecture.

G Google Cloud

Where Google Cloud can be advantageous

  • Strong data and analytics capabilities, including BigQuery for managed data warehousing and analytics.
  • GKE offers Standard and Autopilot modes with different levels of infrastructure control and management.
  • Autopilot can reduce node-management responsibilities for compatible workloads.
  • Useful for organisations whose architecture centres on cloud-native services, analytics and data engineering.

Trade-offs to investigate

  • Check the availability and maturity of the exact services required in target regions.
  • Team familiarity and existing platform skills affect delivery and support costs.
  • Autopilot's managed model reduces some control; Standard offers a different responsibility balance.

Questions for ASK AI and LEARN

Cloud platform questions

Use these as prompts for lessons, comparison exercises and architecture discussions.

Foundations and service comparison

  • What are the advantages and disadvantages of AWS, Azure and Google Cloud?
  • What are the differences between EKS, AKS and GKE?
  • What is the difference between IaaS, PaaS and managed database services?
  • How do regions, zones and availability models differ?

Database and platform engineering

  • How would you deploy PostgreSQL on each cloud?
  • Compare managed database services with self-managed Kubernetes databases.
  • How do backup, point-in-time recovery and object storage differ?
  • How should database monitoring and alerting be designed?

Security, networking and governance

  • Compare IAM, roles, service identities and workload identity.
  • How do private networks, firewall rules and private endpoints work?
  • What should be considered for data residency and compliance?
  • How would you design least-privilege access?

Cost, migration and architecture

  • How do I compare the total cost of the same workload?
  • What are the risks of moving from one cloud to another?
  • How does Terraform manage infrastructure across providers?
  • When is multicloud justified, and when does it add avoidable complexity?
